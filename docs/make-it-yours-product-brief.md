# Make It Yours — product and interaction brief

## Purpose

Help a business compare Foundation and Custom, picture an appropriate direction, clarify requirements, and send one useful brief. This is an agency engagement, not a self-serve template store.

## Offer boundaries

- Foundation adapts a proven public marketing/page system around the brand and audience.
- Commerce Foundation is public product storytelling with links to an existing store. Checkout, payments, inventory, and store connections need a separately scoped Custom build.
- Custom can be an intentional original marketing-site choice or a requirement-driven scope.
- Applications and private workflows are outside the published website estimates. Undecided requirements require review; uncertainty does not automatically mean Custom.
- Starting prices and timelines are indicative. Proposals confirm page count, content, editing tools, revisions, support, migration, taxes, third-party costs, and availability.

## Order

Project-led promise and reference directions → approach comparison with core services and prices → live concept showcase → four-step fit check → explained recommendation → FAQ → one project brief. The result and brief appear after the fit answers are confirmed. Home links carry the direction and genuine project type; no other requirements are assumed.

## Interaction contract

- Requested approach, direction, and functional requirements are distinct state. No duplicate route/type selector inside the brief.
- All required fit answers start empty except a genuine project type carried from Home. Include “Not sure.”
- Direction tabs and question tabs support roving focus, arrow keys, Home/End, and labelled panels.
- Explicit next/back/tab actions position the active rail below the measured header. Use Lenis numeric coordinates to avoid double scroll-margin offsets, native fallback, and instant reduced motion. Selecting an answer does not scroll.
- Show the actual recommendation reasons and accessible summary, with only a short status announcement.
- Edits require reconfirmation and preserve the written brief. Changes to approach/currency/review status require explicit budget reconfirmation.
- Form order: outcome → budget/timing → contact. Required fields and errors are associated programmatically; validation focuses the first invalid field.
- Preserve the full fit context in the submitted goals, since the existing reference field is limited to 80 characters. Tracking serialization is not shown to the visitor.
- Receipt confirms delivery of a brief, not acceptance of scope or reservation of timing.

## Visual language

Use the shared dark surfaces, Syne headings, mono utility text, cyan active rail, hairlines, finite house motion and existing ProjectMedia references. Headings are visible immediately and reference images load eagerly with no scroll-gated entrance. On mobile stack reference media and its caption, and show one question at a time. Reference projects demonstrate capability and are not designs for resale.

## Validation

Run lint, type-check, and build after application changes. Verify Home carry-over, both preferred approaches, checkout/application/uncertainty routing, keyboard tabs, 320/390px layouts, header alignment, brief preservation, budget reconfirmation, validation descriptions, and failure recovery. A real submission requires a deliberately authorized test; routine UI checks must not send enquiries.
